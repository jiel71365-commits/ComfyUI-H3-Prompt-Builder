# 漫剧插件 v2 优化需求清单（待用户确认）

- 日期：2026-08-06
- 状态：需求收集，未批准实施；用户审阅后再决定改哪些
- 现状：v1 已上线可用（剧本→分镜 → 资源映射 → 分镜→镜头提示词 → R2V）

## 需求 1：资源映射自动生成 + 按镜头选图

**用户诉求**：资源映射节点能否直接生成剧本需要的所有资源，再按镜头需要自动选择对应图片输出给 H3。

**可行性结论**：
- ✅ 可做（低成本）：映射节点根据「资源清单」自动生成建议映射文本（按出场顺序自动编号 `角色A=图1`、`角色B=图2`…），用户只需确认或微调，不用从零填写。
- ⚠️ 部分可做（有成本/风险）：全自动「按镜头选图直连 R2V」。图片必须由用户先连进图库节点（绕不开）；ComfyUI 节点输出槽固定，动态选图需要固定 9 槽透传节点或依赖现有图像选择节点（如 Impact Pack / rgthree / easy-use 的 ImageSelector），并按镜头序号选索引。风险：连错难排查、标签顺序出错直接影响一致性。
- 📋 用户提到的「图像选择节点」确实存在（ImageSelector 类），可作为方案的一部分。

**建议**：v2 默认做「自动建议映射」；选图自动化作为可选增强（单独一个辅助节点），先不动主流程。

## 需求 2：API 参数一次配置复用

**用户诉求**：多个节点都要填 api_key/model/base_url，能否加一个节点只填一次。

**可行性结论**：✅ 可做。新增「LLM 配置」节点（输出一个 JSON），各 LLM 节点增加可选 `llm_config` 输入；原单节点 api_key/model/base_url 保留为覆盖项。填一次、接线复用。

## 需求 3：避免重复跑「剧本→分镜」

**用户诉求**：生成镜头二时，会不会又跑一遍剧本→分镜（费 token + 前后不一致）。

**可行性结论**：
- ComfyUI 对输入未变的节点会缓存输出：只改「镜头序号」时只重跑「分镜→镜头提示词」，剧本→分镜不会重新调用 LLM。正常使用不会重复跑。
- ⚠️ 隐患：LLM 非确定性，万一重跑（改过剧本/误触）会产生不同分镜。
- ✅ 加固方案：① 文档说明缓存机制；② 「分镜→镜头提示词」节点的 storyboard_json 输入支持手动粘贴复用（从 Show Text 复制回来，绕开 LLM，前后绝对一致）；③ 分镜阶段用低温度（config 默认可改为 0.2 或提供选项）降低方差。

## 需求 4：禁用字幕与 BGM 选项

**用户诉求**：多段剪辑时字幕/BGM 会很麻烦，提示词输出增加「禁用字幕 + 无 BGM」选项。

**可行性结论**：✅ 直接做。预设节点增加「音频与文字策略」选项（默认：禁字幕 + 无 BGM）；注入两个规则文件：分镜规则避免画面文字需求，镜头提示词规则强制 `non_diegetic_music: N/A` + 画面无字幕/文字/水印。

## 补充建议（用户要求我主动想的）

|---|---|---|

## 建议的实施优先级

1. 必做：需求 4（禁用字幕/BGM）、需求 2（LLM 配置节点）、需求 3 加固（storyboard 粘贴复用）
2. 推荐做：需求 1 前半（自动建议映射）
3. 可选做：补充 A（设定图提示词）、B（链式衔接）、C（批量导出）
4. 暂缓：需求 1 后半（全自动选图）、D、E、F
